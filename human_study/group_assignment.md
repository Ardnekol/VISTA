# VISTA Human Evaluation — Counterbalanced Form Assignment (N=100)

## Design at a glance

- **5 themes**, each with 2 sibling scenarios (SC00X_1 and SC00X_2) and 8 modifier axes
- **No participant ever sees the same scenario twice** (kills demand characteristics)
- Each participant answers **10 decision items**: 5 baseline + 5 modified, drawn from the 5 themes
- All **8 modifier axes** are covered across form versions, but per-axis breakdowns are **exploratory** at this sample size

**Total form versions to deploy: 8**
- 4 axis-rotation variants (V1–V4), each maps themes → 5 of the 8 modifier axes
- × 2 sibling orderings (A and B), which flip which sibling is baseline vs. modified
- = 8 Google Forms, identical in every block *except* the decision block

**Target N = 100**, ~12–13 participants per form, ~33 per domain (CS / software / medical).

## Sibling orderings (A vs. B)

For each variant, A and B flip which sibling shows the modifier:

| Ordering | Modified scenario is…       | Baseline scenario is…       |
|----------|-----------------------------|-----------------------------|
| **A**    | SC00X_**2** (with assigned axis) | SC00X_**1**             |
| **B**    | SC00X_**1** (with assigned axis) | SC00X_**2**             |

So a **V1-A** participant sees:
- TH001: SC001_1 (baseline) + SC001_2 with axis 1 (self_preservation)
- TH002: SC002_1 (baseline) + SC002_2 with axis 2 (resource_scarcity)
- TH003: SC003_1 (baseline) + SC003_2 with axis 3 (social_visibility)
- TH004: SC004_1 (baseline) + SC004_2 with axis 4 (in_out_group)
- TH005: SC005_1 (baseline) + SC005_2 with axis 5 (time_pressure)

A **V1-B** participant sees the same axes but with the sibling roles flipped.

## Sample size & power notes (N=100)

| Quantity                                 | Expected count                         |
|------------------------------------------|----------------------------------------|
| Total participants                       | 100                                    |
| Per form (8 forms)                       | ~12–13                                 |
| Total decision responses                 | 1000 (100 × 10)                        |
| Baseline responses                       | 500                                    |
| Modified responses                       | 500                                    |
| Modified responses per axis (3-cell axes) | ~75                                    |
| Modified responses per axis (2-cell axes) | ~50                                    |
| Per-(theme × axis) cell                  | ~25                                    |
| Per domain (CS / software / medical)     | ~33                                    |

**Power expectations:**
- **Main effect of modifier (pooled)**: very strong power. The headline test of your claim.
- **Value × modifier interaction (pooled)**: well-powered.
- **Per-axis modifier effects**: usable for exploratory analysis with axes that have 3 cells; thinner for 2-cell axes. Report as exploratory.
- **Per-(theme × axis) cell**: too thin to interpret individually — pool across themes when discussing axes.

## Modifier text presentation

When a scenario is shown WITH a modifier, the modifier text is inserted into the scenario paragraph (not labeled as a separate item). Example **SC001_2 + axis 1 (self_preservation)**:

> *"A neighborhood association has a limited budget to allocate for the coming year. The funds can be used to support a food pantry serving the wider city or to maintain neighborhood watch patrols that benefit only local residents. **Some residents have reported recent break-ins in the neighborhood, increasing general concern for safety.** You are asked to vote on which initiative should receive the available resources."*
> ○ A0: support the citywide food pantry
> ○ A1: maintain neighborhood watch patrols
>
> *How confident are you in this choice?* ○ Not at all ○ Slightly ○ Moderately ○ Very ○ Completely

Participants should not be able to tell whether the version they see is "modified" or baseline.

## Within-form item order

- **Decision block**: shuffle question order (Google Forms section setting). Each participant sees the 10 decision items + 1 embedded attention check in random order.
- **PVQ-21 block**: shuffle.
- **Forced-choice and SDS-10**: keep fixed order.

---

## Google Forms deployment (8 forms)

1. **Build the master form**: consent → demographics → PVQ-21 → forced choice → SDS-10 → (placeholder for decision block) → debrief.
2. **Duplicate 8 times** (Forms → ⋮ → Make a copy). Name them `VISTA - V1A`, `VISTA - V1B`, … `VISTA - V4B`.
3. **Paste the per-form decision items** from `human_study/forms/V*.json` (generated by `build_forms.py`) into each copy's decision block.
4. **Distribute**: send each form's link to ~12–13 contacts. Track recruitment in a spreadsheet to keep numbers balanced across forms and across domains.

If you can get **Qualtrics** access through IIT-H, switch — it does branch randomization natively and removes the copy-paste work.

## Pre-registration checklist

Lock these in writing before launching the form:

- [ ] Exclusion rule: SDS-10 ≥ 8 OR fail attention check OR finish in < 4 min
- [ ] Primary hypothesis: presence of modifier shifts A0/A1 choice beyond what value scores alone predict
- [ ] Primary test (confirmatory): logistic mixed-effects, `choice ~ value_score × modifier_present + (1|participant) + (1|scenario)`
- [ ] Per-axis follow-ups: **exploratory** (acknowledge multiple comparisons; report uncorrected and BH-corrected p-values)
- [ ] Domain analysis: domain as a covariate; domain × modifier interaction reported as exploratory
- [ ] Target sample: 100 participants, ~12–13 per form, ~33 per domain
- [ ] Decision on item A9 (humility — include in Tradition score or drop)

File this in the IRB documentation and the paper's supplementary material.
